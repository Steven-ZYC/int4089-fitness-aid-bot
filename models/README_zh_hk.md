負責人：**Zhang Haoyu**；專屬分支：**`Feat-Arduino-Haoyu`**（歷史分支名，目前任務不以 Arduino 韌體為主）。

開始前閲讀根目錄 [AGENTS.md](../AGENTS_zh_hk.md)，確認身分、本人分支及工作區狀態。只在本人分支修改提交；用 PR 申請合併到 `main`。

<a id="最新任务2026-10-30-consultation-后"></a>

## 最新任務（2026-10-30 consultation 後）

**AI 推理暫時在團隊電腦上運行，不要求把模型部署在 ESP32 上。** 數據由 Dong Yuankun 的雙 ESP32 系統提供：ESP32-CAM 採集影像，ESP32-S3 主 ESP 採集 Bosch BMI-series IMU 的運動數據，並負責與電腦的網絡通信。

此目錄應逐步形成可復現的**數據集選擇 → 訓練／驗證 → 電腦端推理 → 姿勢結果輸出**流程。未來若原型驗證可行，可再考慮遷移至雲端 HPC／GPU 服務器；目前不得寫成已上線。

<a id="当前交付要求"></a>

## 目前交付要求

1. **任務定義**：先明確要支持的健身動作、姿勢異常的判定標準、模型輸出（關鍵點／動作類別／錯誤類型等）和可觀測評價指標；不要只以“人體姿態檢測”籠統代替“動作是否標準”。
2. **數據集調查與選型**：對比候選數據集的動作覆蓋、姿勢標註、許可、規模、可用性及數據質量；記錄下載／標註流程、訓練／驗證／測試劃分，避免數據泄漏。無法直接支持姿勢正誤識別的數據集須説明補標或遷移方案。
3. **模型訓練與驗證**：建立最低可用 baseline，保存版本、環境、超參數、預處理與驗證結果；如尚未跑通就標明未訓練，不預報準確率。
4. **電腦端推理服務**：編寫可在團隊電腦運行的影像輸入、推理、後處理與結果輸出流程。和 Yuankun 確認網絡消息格式及攝影機幀、IMU 時間戳的數據介面。
5. **融合策略與指標**：明確第一版使用影像 alone 還是影像 + IMU 融合；如果融合未實現，需明確標記。記錄模型級時延、有效幀率及與系統集成相關的端到端延遲。
6. **交付集成**：給出判斷結果的數據結構（含動作、時間戳、置信度／閾值、反饋類型等可用字段）、測試樣例與運行説明，讓 Yancheng 可以對接 Arduino 的 LED／蜂鳴器提醒。

<a id="协作接口"></a>

本檔案是任務説明，**不代表已選定數據集、訓練成功、驗證模型性能或完成電腦端服務**。不提交可辨識的人像、未授權數據或憑據；模型權重和訓練數據根據項目忽略規則及許可管理。
