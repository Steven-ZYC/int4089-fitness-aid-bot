# 動作規範實時判定（電腦端 AI）

ESP32-CAM 採集 → 電腦上做姿態估計 → 幾何規則判斷動作是否標準 → 網頁實時顯示。

這是「姿勢判斷」這一塊的第一版實現。之前 `esp32_cam_app` 只做到「畫面裏有沒有人」，
本項目真正需要的是「**這個人的動作做得規不規範**」，本目錄補上這一段（入口是 `pose_app.py`，與檢測版 `app.py` 共用 `sources.py`）。

## 方案

```
ESP32-CAM ──MJPEG──> 電腦
                     ├─ YOLOv8n-pose  → 17 個 COCO 關鍵點
                     ├─ 角度計算      → 膝角 / 肘角 / 軀幹傾角 / 左右差
                     ├─ 動作規則      → 閾值判定 + 違規項
                     └─ 狀態機        → 次數統計，在最底點採樣判定
                              ↓
                     網頁 UI（骨架 + 角度 + 判決）
```

**為什麼用規則而不是端到端分類**

| | 規則方案（本實現） | 端到端分類 |
| --- | --- | --- |
| 能否説清"哪裏不對" | 能，逐項列出 | 只能説"不標準" |
| 需要標註數據 | 不需要 | 需要大量 |
| 閾值可調 | 是 | 否 |
| 新動作支持 | 加一組閾值 | 重新訓練 |

邏輯：先用規則跑通閉環，拿到真實數據後再決定要不要訓練分類器做二次校準。

<a id="文件"></a>

## 檔案

| 檔案 | 説明 |
| --- | --- |
| `pose_engine.py` | YOLOv8n-pose 封裝，輸出 17 點關鍵點（多人時取最大框） |
| `form_rules.py` | 角度計算、深蹲/掌上壓規則、計次狀態機 |
| `pose_app.py` | 推理管線 + 網頁 UI（骨架疊加、角度、判決面板） |
| `sources.py` | 影片源（本地攝影機 / ESP32 MJPEG 流） |
| `test_rules.py` | 規則引擎單元測試（合成關鍵點，不依賴攝影機） |

<a id="运行"></a>

## 運行

```bash
# 接 ESP32-CAM（摄像头装歪时加 --rotate）
python pose_app.py --source http://<ESP32_IP>/stream --rotate 270 --action squat

# 用本机摄像头
python pose_app.py --action pushup

# 规则引擎自测（不需要硬件）
python test_rules.py

# 不开 UI，跑 N 帧存图排查
python pose_app.py --self-test 40 --action squat
```

UI: `http://127.0.0.1:8010`

<a id="拍摄要求很关键"></a>

## 拍攝要求（很關鍵）

規則靠關鍵點算角度，**關鍵點不全就等於沒法判**：

1. **全身必須進畫面** —— 深蹲要看到踝關節，只拍上半身算不出膝角
2. **距離 2–3 米**，人佔畫面高度的 60% 以上
3. **側面或正面 45°** 最理想；純正面看不出軀幹前傾，純側面看不出左右對稱
4. **不要逆光** —— 背光時 ESP32-CAM 會把人拍成剪影，關鍵點全丟

目前這台 ESP32-CAM 的畫面只拍到手臂（或頂着天花板），所以膝角恆為 `None`、
階段停在「未開始」，這是取景問題，不是算法問題。

<a id="判定规则阈值都可改见-squat_cfg--pushup_cfg"></a>

## 判定規則（閾值都可改，見 `SQUAT_CFG` / `PUSHUP_CFG`）

**深蹲**

| 指標 | 閾值 | 違規提示 |
| --- | --- | --- |
| 最低膝角 | ≤ 105° | 下蹲深度不足 |
| 軀幹傾角 | ≤ 45° | 軀幹前傾過大（易塌腰） |
| 左右膝角差 | ≤ 20° | 左右不對稱，存在代償 |

**掌上壓**

| 指標 | 閾值 | 違規提示 |
| --- | --- | --- |
| 最低肘角 | ≤ 95° | 幅度不夠 |
| 肩-髖-踝直線度 | ≥ 160° | 身體沒成一條線（塌腰或撅臀） |

計次邏輯：膝角（肘角）經過 EMA 平滑後驅動狀態機
`站立 → 下蹲 → 底部 → 起身 → 站立`，回到站立時結算一次，
並在整個過程中記錄最低角度與最大傾角用於判定。

**注意**：只要開始下蹲就算一次，蹲得淺也會計數——否則"蹲得不夠深"這個最該報的違規會被漏掉。
這個 bug 在單元測試裏被發現了。

<a id="测试结果"></a>

## 測試結果

`python test_rules.py` 全部通過（合成關鍵點，可復現）：

```
[PASS] 角度计算
[PASS] 标准深蹲 计次=1 最低膝角=90.9 分数=100
[PASS] 浅蹲 违规=['下蹲深度不足：最低膝角 131°，建议 ≤105°']
[PASS] 躯干前倾 违规=['躯干前倾过大：63°，建议 ≤45°（易塌腰）']
[PASS] 俯卧撑 计次=1 最低肘角=93.2
[PASS] 塌腰 违规=['身体没成一条线：最小 152°，建议 ≥160°（塌腰或撅臀）']
```

性能：YOLOv8n-pose 推理 **7 ms/幀**（RTX 5080，imgsz 480），端到端幀率受 ESP32 推流限制（約 7–16 FPS）。

<a id="输出数据结构后续回传给-esp32--arduino-用"></a>

## 輸出數據結構（後續回傳給 ESP32 / Arduino 用）

```json
{
  "action": "深蹲",
  "phase": "底部",
  "reps": 3,
  "angles": {"膝角": 92.0, "躯干倾角": 18.0, "左右差": 4.0},
  "last": {
    "rep": 3,
    "ok": false,
    "violations": ["下蹲深度不足：最低膝角 131°，建议 ≤105°"],
    "score": 75
  }
}
```

這個結構由 `/stats` 介面直接返回，也可以改成串列埠/UDP 發給 Arduino 驅動 LED、蜂鳴器。

## 已知限制

- **單目 2D 規則**：膝內扣這類需要俯視/正面精細判斷的問題判不了，只能看膝角、傾角、對稱性
- 關鍵點抖動會讓角度有 ±5° 波動，所以用了 EMA 平滑，代價是響應略滯後
- 只支持深蹲、掌上壓兩種動作；硬拉、卧推的規則需要另加
- 側面拍攝時軀幹傾角有意義，正面拍攝時該項基本失效
- 閾值目前是按運動常識設的，**沒有用真實數據校準**

## 下一步

1. 用真實拍攝的深蹲影片校準閾值（錄 10–20 次，看角度分佈）
2. 增加動作自動識別（先判斷在做深蹲還是掌上壓，再套對應規則）
3. 把判決結果通過 UDP/串列埠發給 Arduino，形成完整閉環
4. 需要更細的違規類型（膝內扣、重心偏移）時，再評估是否訓練分類器
