**狀態：2026-11-03 第 2 步已通過。** 用戶核對六線後，COM9 連續兩次在 0x68 讀到 CHIP_ID 0xD1，見 [身份實測](BMI160_TEST_RESULT.md)。其後第 3 步的 [基礎採集驗收](BMI160_AXES_CALIBRATION.md) 亦完成；完整精密校準等另列後續。沒有模組購買頁或廠商原理圖。

## 這一步要證明甚麼

S3 能執行程式已於 [第 1 步](S3_TEST_RESULT.md) 確認。現在要證明 S3 能透過 I²C 找到這塊紫色模組，並讀到 BMI160 預期的型號代碼。

這一步只讀晶片身份，不修改感測器配置寄存器，也不啟動六軸採樣。讀取時仍會經 I²C 傳送要讀取的寄存器位址。

## 接線依據與電源選擇

- 按你提供的照片，紫色模組有明確的 `VIN`、`3v3`、`GND`、`SCL`、`SDA`、`CS`、`SA0` 標示；S3 有 `3V3`、`GND` 和標示 `4`、`5` 的排針。
- 本方案選擇以 S3 的 3.3V 供應模組的 **3v3 電源軌**，VIN 保持空接，只有 USB 這一個電源來源。這是直接供應 3.3V 軌的方案，不依賴未知廠商 VIN／穩壓器的 5V 相容規格；它不表示已取得模組原理圖。
- 使用前需按照片核對模組確為上述標示；若現物標示不同、3v3 接點意義有疑問或有其他電源，不按本表通電，先核對。
- Bosch 的晶片資料支持 3.3V 電源及邏輯範圍，並建議 I²C 模式將 CSB 固定接 VDDIO；SA0／SDO 接地選 `0x68`。參考 [Bosch BMI160 datasheet](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi160-ds000.pdf)，尤其第 89、93 頁。
- 同類 12-pin 模組的第一手開源接線記錄亦採 3V3 供電、VIN 空接、CS 接 3.3V；這是接法交叉參考，不是你這塊模組的廠商證明：[實作專案 Wiring](https://github.com/nopnop2002/esp-idf-bmi160#wireing)。

GPIO4 和 GPIO5 是本次主動選定的 I²C 資料／時鐘引腳，與程式 `Wire.begin(4, 5, 100000)` 相同。樂鑫 [GPIO 資料](https://docs.espressif.com/projects/esp-idf/en/v5.0/esp32s3/api-reference/peripherals/gpio.html) 列出其一般 GPIO 功能；[Arduino I²C API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/i2c.html) 支持選擇 SDA／SCL。不要把數字 4、5 解讀成第幾根排針。

## 先斷電，再按標示接六根線

先拔掉新 S3 的 USB。舊 CAM、Arduino 和其他感測器維持未連接本次 I²C／電源線。

| S3 接點 | 紫色 BMI160 接點 | 用途 |
| --- | --- | --- |
| `3V3` | `3v3` | 供應 3.3V 電源軌 |
| `GND` | `GND` | 共地，讓兩塊板使用相同的電壓參考 |
| 標示 `4`，即 GPIO4 | `SDA` | 傳送與讀取資料 |
| 標示 `5`，即 GPIO5 | `SCL` | 主控發出通信節奏／時鐘 |
| 另一個 `3V3`，或同一 3.3V 軌 | **`CS`** | 固定高電位，保持主要介面為 I²C |
| 另一個 `GND`，或同一地線軌 | `SA0`／字形似 `SAO` | 接地選定 `0x68` 位址 |

S3 的兩個 3V3 和多個 GND 可分別使用；也可經麵包板分配同一電源軌，但需確認麵包板長電源軌是否中間斷開。每條線均按板上的文字找，不靠線色或照片方向猜測。

本次 `VIN`、`OCS`、`INT1`、`INT2`、`SCX`、`SDX` 留空。特別注意 **CS 和 OCS 不同，SDA／SCL 也不是 SDX／SCX**。

接好後先保持 USB 未插入，提供能看清兩塊板標示和每條線兩端的照片，核對後再上電。目標是一次確認電源極性、訊號對應和接觸可靠性。

## 核對後才上傳身份讀取程式

1. 核對接線，接回 S3 的 COM USB。
2. 開啟 [`BMI160_ID_Check.ino`](BMI160_ID_Check/BMI160_ID_Check.ino)。沿用已成功的 ESP32S3 Dev Module、16MB Flash、OPI PSRAM、CDC Disabled 設定。
3. 關閉其他占用串口的程式，再上傳。此時 S3 上原來的主板自檢程式會被身份讀取程式替換。
4. 打開 Serial Monitor，115200 baud。先前這台電腦的端口為 COM9，重新插拔後仍應按實際端口確認。

以下報告已於 2026-11-03 實際取得兩次，完整記錄見 [BMI160_TEST_RESULT.md](BMI160_TEST_RESULT.md)：

```text
=== BMI160_ID_CHECK ===
SDA=GPIO4 SCL=GPIO5 I2C_HZ=100000
ACK address=0x68 CHIP_ID=0xD1
NO_ACK address=0x69 wire_status=2
PASS: one expected BMI160 identity found. Six-axis acquisition is not tested.
```

`0x68` 是我們要找的 I²C 地址；`0xD1` 是晶片回覆的型號 ID。只有 0x69 無回應，在本次 SA0 接地的單顆模組接法中屬預期現象。完整報告約每 3 秒重複一次。

## 如何理解異常

- 兩個地址都無回應：先斷電，檢查電源、共地、接點、CS／SA0、SDA／SCL。I²C 需要上拉電阻，未知模組的實際上拉尚未量測；不要以通電時隨機換線排查。
- `ACK` 但 ID 不是 `0xD1`：記錄回覆，不直接套用 BMI160 的配置寫入或換成另一型號驅動。板上絲印可能與實際晶片不同，需再辨識。
- `READ_ERROR`、總線超時或無法開始 I²C：檢查設定與線路，先保留原錯誤文字。
- `PASS` 只表示通信與預期身份相符；六軸讀值、校準和採樣頻率是下一步，不能提前標為通過。
